## Why nothing was driven

A concurrent session held the primary checkout for the whole sitting: a live dev stack, three CDP
drives of its own, and eight uncommitted files it never landed. Per
`scripts/devtools/make-worktree.sh`'s own header, **`lerna exec` resolves the package root to the
primary checkout even when launched from a worktree**, so `test:ci` and any editor drive belong to
primary and to nobody else. Running one would have graded their tree, not ours, and collided with
their drives.

So the lanes did what a worktree *can* do — `tsc`, package-local `jest`, and reading source — and
stopped at the line where a claim would have needed a pixel.

⚠️ **`test:ci` has NOT been run on this branch.** The neighbour measured **2692 specs / 6 failures
at seed 64762** on their own tree that day, all six the documented baseline names — but 20 of those
specs were their *uncommitted* work. The committed baseline was **2672**. Take a fresh number; do
not subtract from these.

## Four premises in the phase's own specs that were wrong

Recorded because the phase's stated rule is that a plausible premise about our own code was wrong
twice before it started. It was wrong four more times.

1. **L19** — the two npm packages do *not* do most of LGC-007. Read in published source.
2. **L5** — Do It needed **no ninth `new Function` parameter**; a fragment compiles against the same
   eight. The ninth is free and became LGC-003's.
3. **L7** — `Order.ATOMIC` is *not* what makes the probe precedence-safe. Measured at every order in
   Blockly 12.3.1: all produce identical arithmetic, because `valueToCode` only ever *adds*
   parentheses and parenthesising a call is a no-op. What makes it safe is that the wrapper is a
   **call** at all. ATOMIC kept as an honest declaration.
4. **LGC-004 §4** — ports are not a variable-arity problem. They are separate top-level blocks, and
   `grep -rn "mutator|mutationToDom|decompose"` over `BlocklyEditor/` returns **nothing**. There is
   no mutator dialog here to replace.

Plus two the sweep found in third-party claims: **`disable-top-blocks` greys nothing out** (the
greying is `Blockly.Events.disableOrphans`, in core — LGC-003 §2's static half is one line and zero
bytes), and **every `@blockly/*` `latest` now peer-deps Blockly 13** while we are on 12.3.1, so each
adoption must pin a frozen 12-line release.

### The eight that are genuinely open
5. **`Logic` now collides with itself.** `Logic & Utilities` already has a **sub-category** called
   `Logic`, so the picker shows a rail entry and an unrelated group heading with the same word.
   Revert the rail label, or rename the sub-category (`Booleans & Branching` fits its six)?
6. **"Logic" holds five, not three.** `Javascript2` (*Script*) is defensible; **`CSS Definition`
   under "Logic" is not.** Moving it is taxonomy, not a display string, so it was left and pinned
   with a spec that fails loudly when someone resolves it.
7. **LGC-005 L16 — should the read side get its checks?** Today `get input` gets no connection check
   because nothing coerces at `Inputs[name]`. One line — `registerInputIfNeeded` running
   `coerceToType`, which already exists and is already imported by `node.ts` — turns it on and makes
   a `Number` check honest. This is the `PORT-TYPE-CONTRACT.md` "Direction C" gap arriving from a new
   direction.
8. **LGC-007 §4 — which save path does the regeneration sweep join?** The one thing that lane
   refused to choose unilaterally: it mutates a project from a background sweep, in a repo where
   `EditorSettings` already debounces disk by exactly the 1000 ms quit window in the registers.
9. **LGC-008 F2 — what does "no longer hides the canvas" mean?** The companion pane **already
   exists** (`EditorDocument`'s `FrameDivider` puts the running app beside the graph). What the
   takeover destroys is the *node graph*. Is the criterion met by the canvas being an always-present
   tab in the pane's tab bar — which is what §2 literally describes and what the IwC finding argues
   for — or does it require both on screen at once? **This decides whether a second splitter is
   built at all.**
10. **LGC-008 — two zoom clusters.** Blockly draws its own zoom controls and trashcan bottom-right;
    a split puts our canvas HUD's zoom cluster in the adjacent corner.
11. **LGC-003 — `disableOrphans` writes to the saved program.** Blockly serialises disabled state, so
    opening an existing Visual Function with orphan blocks re-saves it with `disabledReasons` added.
    One-time and legitimate, but **"save, close, reopen is byte-identical" is now true only for
    programs with no orphans**, and the criterion is written that way. If the static tell must be
    non-destructive it has to be drawn like the hollow wash instead — a different feature.
12. **LGC-004 — click-to-create.** Added alongside drag for discoverability; not in the spec, and it
    could equally read as an accidental-creation hazard.
