## Why these are specifications rather than task plans

The task files in phases 12–19 are written to be executed: concrete steps, file paths, testing plans. These are not, and the difference is intentional.

Every document here describes work that is 12–24 months out, downstream of three decision gates, and dependent on which user base turns out to be real. Writing detailed implementation plans now would produce false precision — plans built on assumptions about a product that does not yet have validated users. Worse, detailed plans invite premature starts.

Each file therefore contains: what the thing is, why it might matter, what it depends on, the open questions that must be answered first, and a rough scale. When a gate passes and one of these becomes real, its specification should be expanded into a proper phase with full task documentation at that point — informed by everything learned in the intervening year.
