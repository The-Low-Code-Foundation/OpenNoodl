### D-1 · a clipboard that is not an export reports V8's parser — **FIXED**

`SavedBlocksSection.handleImport` had `importDefinitions(JSON.parse(text), target)` inside one
`try`, so a `SyntaxError` reached the same `showError` as a domain refusal. With `not json at all`
on the clipboard the toast read:

> *Unexpected token 'o', "not json at all" is not valid JSON*

**Fixed** — the parse gets its own `try` and its own sentence, and an empty clipboard gets a
different one. The domain refusals still pass `error.message` through untouched, which is asserted.

### D-2 · the saved-block glyph renders at 1.24:1 in the dark theme — **FIXED**

`SavedBlocksSection.module.scss` `.Glyph` declared `color: currentColor`. **Nothing in that tree
sets `color`** — not `.Row`, not `.Head`, not `CollapsableSection`, not the settings panel, not the
launcher dialog — so it resolved to the document initial `rgb(0, 0, 0)` on `rgb(24, 29, 36)`:
**1.24:1**. It was copied from `CanvasTabs`' `.SavedBlockMark`, where it is correct because `.Tab`
sets `color` two rules above it.

This is *"an icon host that sets `fill` sets nothing"* in a new costume: **a declaration that is
present and losing is invisible to a parser**, and to every spec that asserts the declaration
exists. **Fixed** — it names `--theme-color-fg-default`, the token its sibling `.Name` names
(measured `rgb(166,176,187)` on `rgb(24,29,36)` = **7.69:1**).

### D-5 · the yield can put every window control off the viewport — **FILED**

After the App Config yield moved the window to `left = 512` at `width = 989` on a 1368 px viewport,
its right edge sat at **1501**. The three title-bar controls are right-aligned, so:

```
logic-builder-home @1391  onScreen=false  hitOwn=false
logic-builder-park @1419  onScreen=false  hitOwn=false
Done               @1463  onScreen=false  hitOwn=false
```

None hit-testable. The three right-edge resize handles too. **From that state a builder cannot
press Home — the control that would rescue it — cannot park, and cannot close the window.** Only a
title-bar drag recovers it.

`clampLogicOverlayRect` allows this on purpose:

```ts
// The window may hang off the right and bottom — that is how you get the canvas back without
// resizing — but never so far that there is nothing left to grab …
const left = clamp(rect.left, Math.min(KEEP_ON_SCREEN - width, 0), Math.max(viewport.width - KEEP_ON_SCREEN, 0));
```

*"nothing left to grab"* was written about the **drag** affordance, which is on the left. VFN-005
then put three controls on the right. A rule right about its old subject.

**Filed rather than fixed**, because the narrow correct fix — make `moveLogicOverlayClearOf` refuse
a candidate that pushes the controls off-screen, and fall through to its existing `'park'` answer —
changes a ruling the task file argues for explicitly (*"the overhang the clamp already allows is a
supported placement"*). A manual drag to an overhang should stay allowed; the **automatic** yield
producing an unusable window should not.

### D-6 · every one of VFN-011's seven strip sentences still clips at 640 px — **FILED**

**This is the flagship's teaching copy, and the gate that says it fits is measuring the wrong
thing.**

At the 640 px window floor the note's box is **488.4 px**. Measured in the renderer
(`canvas.measureText` at the element's own computed `11px -apple-system`, cross-checked against a
DOM `Range` on the live element — **518.6 = 518.6**, so canvas is faithful here):

| reason | rendered | box | over |
|---|---|---|---|
| `waiting` | 490.0 | 488.4 | +1.6 |
| `no-preview` | 552.7 | 488.4 | **+64.4** |
| `not-in-preview` | 549.4 | 488.4 | +61.0 |
| `no-connection` | 522.7 | 488.4 | +34.3 |
| `attached-idle` | 518.6 | 488.4 | +30.2 |
| `no-probes` | 550.2 | 488.4 | +61.8 |
| `no-node` | 556.3 | 488.4 | **+67.9** |

Live, `attached-idle` renders as *"…Or press ▶ Run to work them out here, app "* — **"stopped."**
is gone. The task file claims *"All seven now 422–480 px against a 489 px budget"*.

**Root cause — the instrument, not the copy.** `scripts/devtools/text-advance.js` sums raw glyph
advances out of `SFNS.ttf`. It reports **447.5 px** for the string the renderer draws at **518.6** —
**16 % low at 11 px**, because macOS applies SF's optical **tracking** at small sizes (~0.067 em
here) and the advance table does not carry it. The declared ±5 % band does not cover it, and the
gate passes with every sentence clipping.

Two things are owed and they are separable:

1. **Fix the instrument.** Either add a tracking model to `text-advance.js`, or — better — grade the
   budget in the renderer, where `canvas.measureText` was proved equal to a `Range` measurement to
   0.1 px. `tests-unit/vfn-011/strip-copy.spec.ts` is otherwise well built and its three controls
   stay valid.
2. **Re-trim against the corrected numbers.** Not attempted here: choosing which words to lose is
   the decision VFN-011 already made once, and it should be made against real numbers rather than by
   me shaving 68 px off somebody else's sentence.

### D-7 · the save outline is never removed — **FIXED**

**Reproduce:** right-click a block → hover *Save as a block…* (outline appears) → click it → the
dialog opens → save or cancel. **The outline stays on the workspace.** Measured: 7 outlines still
painted through eight polls over 5.6 s, with no dialog open and nothing hovered.

`MyBlocksSaveOutline` keeps two requests, `hovered` and `pinned`, and `render()` falls back to
`hovered` when `pinned` is null. Clicking the menu item destroys the row **with the pointer inside
the label**, so its `pointerleave` never fires and `hovered` is never withdrawn. The dialog's
unmount `unpin()` therefore dropped only its own request and `render()` went straight back to the
stale hover.

**Fixed** — `pin()` clears `hovered`. A pin takes over *and finishes* the hover in one step, which
keeps the class's stated property (no frame between the menu closing and the dialog mounting in
which nothing is outlined) that a `hide()` from the callback would have broken.
