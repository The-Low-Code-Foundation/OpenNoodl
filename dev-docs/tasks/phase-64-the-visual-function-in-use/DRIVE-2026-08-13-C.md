## ✅ The ports fix (`vfn-c-ports`) — driven, and the migration path works

`NOTES-ports.md` owed drive 1. Merged into `cline-dev`, webpack rebuilt, editor **reloaded** (HMR
leaves the mounted editor on the old module), project reopened.

**Before the flush** — the node's outputs were `total` only; `hasResult: false`. Correct, and worth
stating: the call block in this fixture was saved *before* the fix, so its `extraState` had no
`ports` and `detectIO` reads the raw persisted workspace.

**After nudging one block to force a flush:**

```
call block extraState.ports:
  { inputs: [], outputs: [ { name: "result", kind: "value", type: "number", declared: true } ] }

node c6 outputs:  … total (*, Outputs), result (number, Outputs)
hasResult: true
```

🔴 **This is the part that could have failed and did not: an existing call block migrates.** The
`ports` stamp is re-derived by `loadExtraState` when the workspace loads, and the next flush writes
it into the persisted workspace, where `detectIO` sees it. No hand-editing, no re-placing the block.

⚠️ **Still owed on this fix:** that the port *accepts a wire* (needs a real drag on the canvas), and
owed drives 2–4 in `NOTES-ports.md` — dragging a saved block into a second Visual Function, rails and
bench agreement, and LGC-007 §4's regeneration sweep.

🔴 **Also found, and it is not in any writeup:** the call block is **not top-level**. `hatMigration`
has wrapped it in a `noodl_when_signal` hat with the derived id `hat-dj.q6i@4A87Q9Xw.17YD`, so
`getTopBlocks()` does not find it and `getAllBlocks(false)` is needed. Any future instrument that
looks for a call block among the top blocks will report it missing.
