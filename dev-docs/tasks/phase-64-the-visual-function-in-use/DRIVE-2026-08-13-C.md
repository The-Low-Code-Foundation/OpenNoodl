## 🔴 VFN-004 — FAILS LIVE. The away mark never appears and the tab never navigates

`NOTES-window.md` graded criteria 2, 3, 4 and 6 as *"decision proved, consequence owed"* and warned
at owed item 5 that a missing `componentId` would be a **quiet** failure worth looking for
explicitly. **It is there, and the cause is not the one the note guessed.**

### What was measured

Opened the Logic Builder on `c6` in `/ErgCodes`, navigated the canvas to `/App`, clicked the tab:

```
activeComponent after click : "/App"      ← did not navigate
selectedNodeIds             : []          ← did not select
data-away                   : "false"     ← while demonstrably away
tooltip                     : "Blocks for Visual Function, in /ErgCodes. Click to select the node."
```

### It is not the event, and it is not the predicate

Both alternatives were eliminated before filing, because either would have made this an instrument
error rather than a defect:

- **The event fires.** A listener attached to `activeComponentChanged` recorded `["/ErgCodes",
  "/App"]` across the two navigations, and `getActiveComponentId()` correctly returned `/App`'s id
  at read time. The derivation is live and correct.
- **The predicate is correct in both polarities**, exercised directly:
  `isTabAway({componentId: active}, active) === false`,
  `isTabAway({componentId: other}, active) === true`,
  `isTabAway({}, active) === false`.

### The cause: **component ids are not persisted, for most components**

```
/App       id: "eeee-0000-0000-0000-000000000017"
/ErgCodes  id: undefined      ← the tab's component
/ErgFail   id: undefined
/ErgRest   id: undefined
/ErgRig    id: undefined
/ErgStates id: undefined
/Item      id: "eeee-0000-0000-0000-000000000021"
```

`id` is an **own property whose value is `undefined`** on the model, and `project.json` confirms it
is simply not written for those components. Checked three separate projects — `vfn64-drive`,
`lgc010-drive`, `lgc002-qa` — and every one is **2 of 7**.

So `LogicBuilderWorkspaceType`'s `const componentId = component?.id` is `undefined` for ~70% of
components, `CanvasTabsContext` faithfully stores `undefined`, and `isTabAway` — correctly, by its
own stated rule that *"an absence of knowledge must not be published as an assertion"* — returns
`false` forever. The tab then falls through to the `select` branch and tries to select `c6` on a
canvas it is not on, which does nothing.

🔴 **Every layer here behaves exactly as designed. The feature is still dead**, because the field it
was built on is usually absent. That is why nothing in the headless suite caught it: every spec
supplies a `componentId`, because the author reasonably assumed components have ids.

⚠️ **This is a decision for the VFN-004 owner, not a patch to apply blind.** `fullName` is the
identifier the rest of the editor actually uses (`switchToComponent`, the exporter, the compiler all
walk `owner.owner` and read names), and it is already carried on the tab as `componentPath` — but a
rename would silently break a tab keyed on it, which is presumably why `id` was chosen. The options
are to key on `fullName`, to assign ids on load, or to persist them. **Do not just swap the field
without deciding what a rename should do.**
