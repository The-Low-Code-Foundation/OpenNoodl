# Drive — 2026-08-13, session D · VFN-004 fixed and driven

The follow-up to [DRIVE-2026-08-13-C.md](DRIVE-2026-08-13-C.md), whose headline finding was that
VFN-004 **fails live**. Fixed, and driven in the primary checkout on `cline-dev`. Fixture:
`vfn64-drive`, component `/ErgCodes`, node `c6`.

## What the diagnosis got right, and the one thing it got wrong

Session C's cause was correct: `component.id` is `undefined`, `isTabAway` therefore returns `false`
forever by its own correct rule, and the click falls through to a `select` on a canvas it is not on.

It was wrong only in **scope**, and the correction matters because it changes the fix:

| | components | with an `id` |
|---|---|---|
| **v2** projects (`components/` dir) | ~180, across ~20 projects | **all of them** |
| **v1** legacy (one `project.json`) | 7 × 3 projects sampled | **2 of 7**, every time |

So it is not "70% of components in the product". It is **v1 legacy projects**, where the format never
promised an id and `ProjectImporter` explicitly refuses to fabricate one. All three projects session C
sampled — `vfn64-drive`, `lgc010-drive`, `lgc002-qa` — are v1.

## The decision, and why the obvious fix was rejected

Session C left the identity question open: *"key on `fullName`, assign ids on load, or persist them —
decide what a rename should do first."*

🔴 **Assigning ids on load was rejected, and there is a live gate saying so.**
`tests/models/ProjectIdentity.test.ts` (DSG-007) rules on exactly this for the sibling field:

> *"The fix must not start minting ids on load — that would write a fresh identity into every legacy
> project the editor opens, and two copies of one project would then diverge silently."*

The argument transfers to components with **more** force, because copying a project directory is the
normal gesture in this register — `vfn64-drive` **is** a disk copy of `vfn64-qa`. Open both and each
mints different guids for the same components; `ProjectMerge` keys components by `id ?? name`, so the
two copies would then read as **delete + add on every component**, where today they key by name and
match.

🔴 **Keying on `fullName` was rejected** because a rename orphans the tab — the trap the task file
named in its own margin (*"navigate by id, resolve the name for display"*). A deterministic id derived
from the name is the same thing wearing a hat.

⚠️ **One argument for minting was withdrawn as overstated.** It looked like four other consumers were
silently degraded on v1 (`componentpicker`, `ProjectMerge`, `inventory`, `MyBlocksProjectScan`,
`ProjectScanner`). Checked in source: the first two already fall back to the name (`id || name`,
`id ?? name`) and the rest only emit `id` into a report. That was most of the case for a broader
repair and it is not real.

## What was built

`models/componentIdentity.ts` — `componentInstanceId(component)`, a session identity:

- **held in a `WeakMap` keyed on the model**, so there is no own property on `ComponentModel` at all.
  It cannot be written by `toJSON`, cannot be caught by a generic serialiser, cannot be clobbered by
  `Model.prototype.set` (which blindly assigns `this[i]` — a getter would have thrown), and does not
  appear in `Object.keys`;
- minted lazily, stable for that model object, **rename-proof**;
- `undefined` for a missing component, so the *"a tab with no key is never marked away"* guard still
  has something to guard.

Both ends now key on it: `LogicBuilderWorkspaceType` (the emit site) and `getActiveComponentId` /
`findComponentByInstanceId` (the readers). They mint from the same function off the same model
objects, so neither can be `undefined` while the other is not.

## 🔴 One near-miss worth recording

The first read of the post-click selection was `[]`, and it was about to be filed as *"navigates but
does not select"*. **There is no `ed.selection`** — the accessor is `ed.selector._selected`. Reading a
property that does not exist returns `undefined` and maps to an empty list, which is indistinguishable
from a real empty selection.

⚠️ **A `[]` from an accessor you have not verified exists is not a measurement.** The node was
selected the whole time. Same family as session C's "suite of absences", one level lower down.
