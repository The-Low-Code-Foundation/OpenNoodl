### AC1 — the nav gains a link, live, with the no-reload half proven

Driven **the person's way**: a draft was titled `The Bindery Journal`, given a slug and
`Show in navigation`, saved, then published through the panel's own `More → Publish`
(`POST /functions/publishPage`).

The anonymous site, watching: nav went
`PUBLISHED CANARY S47 | Our Studio` → **`The Bindery Journal | PUBLISHED CANARY S47 | Our Studio`**,
with `stampAlive` **unchanged** (`STAMP2-1788413177424`) — AC1's *"no-reload half proven (e.g. a
stamped window property surviving the update)"*, verbatim.

🔴 **A trap this run paid for, and it was mine, not the product's.** The first attempt published by
writing `published: true` over REST. The nav did not gain the link — and the honest reading was
**not** "live propagation is broken". Reading the ACLs showed why:

| published via | ACL |
|---|---|
| the panel's `Publish` | `{"role:admin": …, "*": {"read": true}}` |
| my REST write | `{"role:admin": …}` — **admin only** |

`published: true` is a flag; the **ACL** is the gate, and `publishPage` sets both. My write did half
the job and the site behaved correctly. ✅ **Check what the product's own path does before calling a
difference a defect.**

## 6. The instrument

**One persistent headless Chrome per context**, own CDP port, own profile, pointed at the static
deploy folder. Promoted out of the scratchpad this time:
**`scripts/devtools/drive-page.js`** — s46's scripts were written twice and lost twice.

Verbs: `start/goto/look/dom/click/clickish/clickat/fill/eval/shot/resize/requests/errors/stop`.
Session state in a JSON file, so `DRIVE_STATE=` gives you several independent browsers — this run
held four at once (owner-on-deploy, anonymous-on-deploy, anonymous-on-no-backend, the `bodyScroll`
arm).

**Traps built into it, each one paid for:**

- 🔴 **`Sign in` matched the heading AND the button**, heading first — and the click reported
  reachable, successful, and did nothing. Same family as s46's `Published` winning a query for
  `Publish`. ⇒ **`--button` restricts the census to pressable elements**, and every result names
  what it matched.
- 🔴 **`document.body.scrollHeight` is `0` on a viewer page** — `#root` is `position: fixed`, so the
  body has no content box. Taking page height from it **silently crops every full-page screenshot
  to one viewport**; the first step-7 picture was cropped at 813 of 1604px and looked fine.
  ⇒ height is taken from the tallest `scrollHeight` in the tree.
- 🔴 Inputs addressed **by DOM order**, never by id — the viewer mints a fresh `input-<uuid>` per
  re-render (s46).
- 🔴 `elementFromPoint` before every click; `<title>` filtered out (zero area, matches everything).
- ⚠️ **A request captured in a later invocation is a different attachment and sees nothing** — so
  the action verbs report the requests *they* caused, in their own call.
- ⚠️ `resize` exists **only** to get past D40 so the thing behind it can be measured. It is
  labelled in the source as a workaround a person does not have.
