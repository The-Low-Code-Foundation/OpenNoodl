## Category summary

| | |
|---|---|
| Nodes audited | 7 / 7 |
| Nodes with ≥1 defect | **6** (Inverter is clean) |
| Distinct defects | 12 |
| **New, not already on record** | **5** |
| Already filed elsewhere | 2 — Condition's class-G entry (NDA-017) and its `getInspectInfo` branch (PLAT-003 §25) |
| C1 closed | **22/22 ports**, whole category |

The five new ones:

1. **`Value Changed` cannot see an Object or Array being edited** — the reactivity contract meeting
   NDA-002's identity guarantee. The highest-impact defect in the category, and the one most likely to
   have cost somebody an afternoon.
2. **`Switch` announces a state change at page load** when `State` is authored.
3. **`And`/`Or` coerce a cleared input to `false`** where `Inverter`, in the same category, abstains
   and documents why.
4. **`Or` flags its output on input rather than on answer**, and compares raw where it coerces — while
   `And`, the matching node, does both correctly.
5. **`Signal To Index` sends its signal before updating its index**, which defeats the node's only
   purpose. Deprecated, so it feeds the deprecated-five question rather than a fix.

**Find rate: 7/7 nodes, 6 with defects, 5 new.** No decline — the category is one of the smallest and
simplest in the library and still produced five, which matches the Variables calibration (4/4, 3 new)
rather than contradicting it. **Do not stop here.**

Nothing in this category is blocked on a decision except the `Value Changed` fix, which needs one:
comparing aggregates by content would make the node fire on every keystroke into a bound Object, so
the honest options are a **Deep Compare** input, a documented limitation (done — the port sentence now
says it), or routing authors to the Object/Array change signals instead.
