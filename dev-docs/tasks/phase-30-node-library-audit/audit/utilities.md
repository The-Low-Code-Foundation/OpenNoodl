### The `numbered-inputs` documentation hole — a **third** invisible port mechanism

`Index To String` and `String Mapper` both build their real port sets from `numberedInputs`, and
**`registerNumberedInput` produces no metadata entry at all** (`nodedefinition.ts:100-131`): the
ports are registered on the instance when a connection asks for one, and never reach
`metadata.inputs`. So a `description` written on a numbered family goes nowhere, and the catalog,
the semantic validator and the AI authoring loop cannot see the ports exist.

That is the same shape as NDA-005 §2's `sendDynamicPorts` gap and this category's Port Editor gap,
at a third mechanism. **Three of the library's four dynamic-port mechanisms carry no documentation
channel**, which is worth stating as one finding rather than three: NDA-005's coverage percentage
measures the one mechanism that does.
