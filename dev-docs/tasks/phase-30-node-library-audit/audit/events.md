## Shared observation — the channel is a bare string on both sides

`Channel Name` on the sender and `Channel` on the receiver agree by string comparison and nothing
checks that the other end exists. Defect class **D**, and the *only* thing either node reports is the
sender's empty-name case (`eventsender.ts:47-53`, added by NDA-004 §2). **A typo'd channel is
completely silent at both ends** — the sender dispatches into an empty listener list and says `Sent`,
and the receiver registers a listener nobody will ever call.

This one is more tractable than most class-D instances, because the editor already has the answer:
`eventreceiver.ts:158-169` walks `graphModel.getNodesWithType('Event Sender')` and matches on
`channelName` to derive the payload ports. **A check for "no sender/receiver uses this name" is the
same walk with a different question**, and it belongs in `setup` — where NDA-009 §1's is.
