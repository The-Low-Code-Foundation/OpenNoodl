# The Chat page

This is a page component ([Chat](noodl-node:4fa882ec-634a-468b-8d57-a869da90d73c), URL path `chat`), holding a nav bar ([/Nav](noodl-node:f1c0926a-2461-450d-81a6-4ec44cfecc03)) and a self-contained chat UI. Its whole purpose is described right on the page by an explanatory [Text](noodl-node:a993b455-5ef3-43f4-834a-4568485ab42d): a prompt goes out over a streamed POST, tokens come back one at a time, and the transcript lives in a global store named `chat` so any other page reading that store sees the same conversation. The page itself takes no inputs — everything it needs (the running conversation) comes from that shared store, not from page params.

**Sending a message.** Typing in the [Text Input](noodl-node:59756b87-c634-4c77-80e1-6a3d6b8d76a1) and either pressing Enter or clicking [Send](noodl-node:f4aa70af-b0c5-41e5-8b3c-2189be8f143b) triggers two things in parallel: a [Function](noodl-node:8466e2dd-7aef-47f1-8068-a1b85a27741b) that builds the HTTP request (headers, body) from the prompt and tells the [Server-Sent Events](noodl-node:1346ccf9-0dec-4fd8-8ea9-d052bc9559ee) node to connect, and a separate [Function](noodl-node:3850205a-b1ba-4e59-8480-6597b7ef632d) that appends the user's turn onto the existing message list (read from [Subscribe to Store](noodl-node:272726ac-0fe2-471c-8e88-0d90b1b4fc6e)) and writes the result back via [Set Global Store](noodl-node:5bdd4d6f-b9c3-4f88-8c06-17b3e55d9f3d) under key `messages`. So the user's own message and the outgoing request fire off together, not one waiting for the other.

**Receiving the stream.** When the SSE connection opens, `onOpen` clears the [Text Accumulator](noodl-node:cef7f30c-f86f-4a03-847b-948157c265a2); each `onMessage` appends the latest `text` chunk to it, and the growing `accumulated` string drives a live-updating [Text](noodl-node:0f4958bf-b423-49c6-88cc-8c75d011d525) that's only visible while `connected` is true — this is the answer appearing token by token. When the stream closes (`onClose`), a [Function](noodl-node:aa8d77d0-863a-4bf8-8b97-f195c975a2b9) takes the finished `accumulated` answer plus the current messages list and appends the assistant's full turn, writing it into the store via [Set Global Store](noodl-node:e1c8126a-ae12-4dd7-81df-32efc93208de); a second [Set Global Store](noodl-node:447caf2a-2074-4fdf-8025-87d8c4a80ee6) simultaneously stashes the raw answer text under key `answer`. Clicking [Stop](noodl-node:d7cfcc00-f5cc-4b3c-8342-59075a8b9cf2) fires `disconnect` on the SSE node directly.

**Transcript and diagnostics.** The full message history from [Subscribe to Store](noodl-node:272726ac-0fe2-471c-8e88-0d90b1b4fc6e) also feeds the [Repeater](noodl-node:c07d196f-a238-4852-8c4e-ac345bbb4227) (template `/Message Row`), which renders the conversation as a list — this is the actual chat log on screen. Below the input, a small diagnostics row of labeled dashes ([Connection](noodl-node:51d9f785-9054-4d22-89b0-e29750ee0f32), [Retries](noodl-node:c9b7311b-b36f-468b-862a-ff08c132cd3d), [Delivery](noodl-node:ae64ea9c-65ca-471c-883b-5b0b4d48341c)) is wired straight to the SSE node's `connectionState`, `retryCount` and `deliverySemantics`, plus an error line ([Text](noodl-node:6bb80468-1830-4f4b-8a5d-626612aed321)) bound to `lastError` — giving a live view of the stream's health rather than just the chat content.
